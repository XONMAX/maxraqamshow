# NikBozor: a marketplace for numbers and usernames

> **v2 — strict monochrome redesign + monetization.** See
> [`docs/MONOCHROME_UX_MONETIZATION_SPEC.md`](docs/MONOCHROME_UX_MONETIZATION_SPEC.md) for the design system, dimensions,
> motion rules and the monetization architecture. Native reference implementations live in
> [`native/ios`](native/ios) (SwiftUI) and [`native/android`](native/android) (Jetpack Compose).

A mobile-first escrow marketplace for **📞 phone numbers**, **Telegram usernames** and **Instagram usernames**.
It's built with Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Framer Motion, TanStack Virtual and Zustand, and it's an installable PWA.

```bash
npm install
npm run dev          # http://localhost:3000
npm run build && npm start
```

Copy `.env.example` to `.env.local` to turn on the real Telegram Login Widget:

| Variable | Where | Purpose |
|---|---|---|
| `NEXT_PUBLIC_TG_BOT_USERNAME` | client | Bot username for the widget. In @BotFather, run `/setdomain` for your domain. |
| `TELEGRAM_BOT_TOKEN` | server only | Checks the widget's HMAC signature in `POST /api/auth/telegram`. |

If these aren't set, the app shows a **demo login** button so every flow still works.

## How the feed works (v2)

- **Home** = sticky header (logo · `[PRO]` + coin balance · sort) + type tabs, then a scrolling body:
  a **single-line product carousel** (`ProductRow`, 132×116 tiles, scroll-snap x) followed by a
  **dense list of 56px post rows** (`PostList`, virtualized, 20 per page).
- **Promoted slots:** the first 2 tiles are boosted/sponsored items with an `[AD]` / `[BOOSTED]` pill and a solid border.
- **Fade + blur:** one `IntersectionObserver` per scroll container writes `data-vis` on each card; the `.fade-blur`
  CSS utility animates only `opacity` and `filter: blur()` (in / edge 45% + 2px / out 0% + 6px). Reduced motion → opacity only.
- **Freemium gate:** premium listings' value, description and the seller contact are blurred (`LockedBlur`) with an
  "Unlock" trigger; `BillingManager` (`lib/billing.ts`) decides what is visible.
- **Billing:** `useBilling()` is the view-model; `BillingProvider` is the adapter (`demoProvider` ships; plug
  StoreKit 2 / Play Billing / Payme via `setBillingProvider`). Pricing rules live in `PRICING`.

## Demo-only parts

These are simulated on the client and are where a real backend would plug in:

- payments
- SMS and bio-code ownership checks
- deal step progression (paid → transferring → delivered on timers; the buyer confirms the last step)
- new listings, which are stored in `localStorage`

Every demo item shows a **DEMO** badge. Demo phone numbers use the fake operator code `00`.
